# 멀티 테넌시 설계 (범용 SI 서비스 전환)

> 상태: **설계안 — 구현 전 결정 필요.** 아래 "결정할 것"이 정해지면 단계별로 구현한다.

지금 ABMS 는 한 회사(데모: (주)애버커스)의 데이터만 담는 구조다. 여러 SI 회사가 같은 서비스를 쓰려면
모든 업무 데이터에 **테넌트(회사) 경계**를 두고, 다른 회사 데이터가 절대 섞이지 않게 해야 한다.

## 1. 현재 구조에서 영향 받는 것

| 항목 | 현황 | 필요한 변경 |
|---|---|---|
| 테이블 | 업무 테이블 28개 (V1~V8) | 기준 데이터(`tb_permission`)를 뺀 전부에 `tenant_id` |
| 유니크 제약 | 14개 (`username`, `email`, 활성 코드/이름, 원가 정책 연·유형, 월 마감 등) | `(tenant_id, …)` 로 범위 변경. `username` 은 전역 유지 여부 결정 필요 |
| JPA 조회 | Spring Data 메서드 + `@Query` 9곳 | Hibernate `@TenantId`(구분 컬럼 방식)로 자동 필터·자동 입력 |
| JDBC 직접 조회 | 변경 이력(`AuditEventListener`, `AuditQueryService`) | `tenant_id` 를 직접 넣고 조건에 추가 |
| 시스템 그룹·원가 정책 | 전역 1벌 (V2 기준 데이터) | 테넌트 생성 시 복사 (테넌트별 수정 가능) |
| 최고 관리자 부트스트랩 | 계정이 하나도 없을 때 1명 | 테넌트 생성(가입) 흐름으로 대체 |
| 배치 (손익 재집계) | 전체 1회 | 테넌트별 반복 실행 |
| 첨부 파일 저장 경로 | `{root}/yyyy/MM/uuid` | `{root}/{tenantId}/yyyy/MM/uuid` |
| AI 어시스턴트 | 사용자 권한 범위 | 테넌트 필터가 함께 걸리는지 테스트로 보장 |

## 2. 방식 비교

| 방식 | 장점 | 단점 |
|---|---|---|
| **A. 공유 스키마 + `tenant_id` (권장)** | 운영 단순(DB 1개), Hibernate `@TenantId` 로 누락 위험 감소, 테넌트 추가가 데이터 1행 | 쿼리 실수 시 데이터가 섞일 위험 → 테스트로 막아야 함, 대형 고객 분리 어려움 |
| B. 테넌트별 스키마 | 격리 강함, 백업·삭제 쉬움 | 마이그레이션을 스키마 수만큼 실행, 커넥션·운영 복잡 |
| C. 테넌트별 DB | 격리 가장 강함 | 비용·운영 부담 가장 큼 |

초기에는 **A** 로 시작하고, 격리 요구가 큰 고객이 생기면 B/C 로 옮길 수 있게 `TenantContext` 를 한 곳에서만 쓰도록 만든다.

## 3. 결정할 것 (사용자 결정 필요)

1. **테넌트 식별 방법**: 서브도메인(`acme.abms.app`) / 로그인 시 회사 코드 입력 / 이메일 도메인으로 자동 판별
2. **로그인 아이디 범위**: 전역 고유(한 사람이 한 회사) vs 회사별 고유(같은 이메일이 여러 회사에 존재 가능)
3. **가입 방식**: 셀프 가입(회사 생성 → 최고 관리자) vs 운영자가 생성
4. **서비스 운영자(슈퍼 관리자)** 필요 여부와 권한 (테넌트 목록·정지·사용량)
5. **기존 데이터**: 현재 데이터는 테넌트 1번으로 옮김 (데모 포함)
6. **요금·한도**: 사용자 수·저장 용량 제한을 둘지

## 4. 구현 단계 (A 방식 기준)

1. `tb_tenant` 생성, 모든 업무 테이블에 `tenant_id`(기존 행 = 1) 추가, 유니크 제약 범위 변경
2. `BaseEntity` 에 `@TenantId tenantId`, `CurrentTenantIdentifierResolver` 가 로그인 사용자(`LoginUser.tenantId`)에서 값을 읽음
3. 로그인·세션에 테넌트 포함, 테넌트 식별(결정 1) 구현
4. JDBC 직접 조회(변경 이력)·배치·첨부 경로에 테넌트 반영
5. 테넌트 생성 시 시스템 권한 그룹·원가 정책 복사, 최고 관리자 생성
6. **격리 테스트**: 테넌트 2개를 만들고 모든 목록·상세·검색·명령 팔레트·AI 도구·첨부 다운로드에서 상대 데이터가 보이지 않는지 검증
7. 화면의 회사 고유 표기(로고·회사명) 를 테넌트 설정에서 읽기
