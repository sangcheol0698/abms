# 도메인 모델

패키지는 기능 단위로 나뉘며(`kr.co.abacus.abms.<feature>`), 엔티티가 업무 규칙을 직접 검증합니다.
테이블 정의는 `src/main/resources/db/migration/V1__schema.sql`을 기준으로 합니다.

## 1. 공통

| 타입 | 설명 |
|---|---|
| `BaseEntity` | `id`, 감사 컬럼(`createdAt/By`, `updatedAt/By`), 소프트 삭제(`deleted`, `deletedAt/By`) |
| `Money` | 원 단위 금액(소수점 반올림). `MoneyConverter`로 `DECIMAL(19,0)` 컬럼에 매핑 |
| `Period` | 시작일 + (선택) 종료일. 종료일이 없으면 진행 중. 시작일 > 종료일 금지 |
| `BusinessException` | 업무 규칙 위반. 메시지가 그대로 화면에 노출됨 |

소프트 삭제된 행은 `@SQLRestriction("deleted = false")`로 조회에서 제외합니다.
단, 직원은 삭제 후 복구 기능 때문에 조회 조건을 명시적으로 겁니다.
코드/이름이 고유해야 하는 테이블(부서 코드, 협력사명, 프로젝트 코드, 매출 차수)은
`deleted = 0`일 때만 값을 갖는 **생성 컬럼(generated column)** 에 유니크 인덱스를 걸어 삭제 후 재사용을 허용합니다.

## 2. 조직

### Department (부서)
- `code`, `name`, `type`(전사/본부/담당/팀/연구소/TF), `parentId`, `leaderEmployeeId`
- `DepartmentTree`: 전체 부서로 트리를 구성해 하위 부서 탐색(`subtreeIds`), 경로(`path`), 들여쓰기 목록(`flatten`)을 제공
- 하위 부서·소속 직원·주관 프로젝트가 있으면 삭제할 수 없음

### Employee (직원)
- `departmentId`, `name`, `email`, `joinDate`, `birthDate`, `position`(직급), `grade`(등급), `type`(고용유형), `status`, `avatar`, `resignationDate`, `memo`
- 상태: `ACTIVE`(재직) → `ON_LEAVE`(휴직) / `RESIGNED`(퇴사) → `activate()`로 복귀
- 규칙
  - 퇴사일은 입사일 이후, 퇴사자는 수정·승진 불가
  - 승진은 현재보다 낮은 직급 불가, 같은 직급·등급으로 변경 불가
  - 삭제 시 이메일을 `deleted.{timestamp}.{원래 이메일}`로 마스킹하고, 복구 시 되돌림
- 이력: `Payroll`(연봉, 기간), `PositionHistory`(직급·등급, 기간)
  - 새 연봉 등록 시 진행 중 연봉은 적용일 전날로 종료
  - 퇴사 시 진행 중 연봉/직급 이력 종료

## 3. 사업

### Party (협력사)
- `name`(활성 행 기준 고유), 대표자, 영업 담당자 연락처
- 프로젝트가 연결된 협력사는 삭제 불가

### Project (프로젝트)
- `code`(고유), `name`, `partyId`, `leadDepartmentId`(주관 부서), `status`, `contractAmount`, `period`(종료일 필수)
- 상태: 예약 / 진행 중 / 완료 / 보류 / 취소
- 삭제 시 하위 매출 계획과 투입 정보도 함께 소프트 삭제

### ProjectRevenuePlan (매출·청구 계획)
- `sequence`(차수, 프로젝트 내 고유), `revenueDate`(청구일), `type`, `amount`, `issued`(세금계산서 발행 여부), `memo`
- 매출 계획 합계는 계약금액을 넘을 수 없음
- 발행된 계획은 삭제 불가(발행 취소 후 삭제)

### ProjectAssignment (투입)
- `projectId`, `employeeId`, `role`(PM/PL/개발자/기타), `period`
- 규칙
  - 투입 기간은 프로젝트 기간 안 (프로젝트 종료일이 있으면 투입 종료일 필수)
  - 입사일 이전·퇴사일 이후 투입 불가
  - 같은 직원은 같은 프로젝트에 기간이 겹치게 투입될 수 없음
- `manMonth(YearMonth)`: 해당 월 투입일수 ÷ 월 총일수 (소수 첫째 자리 반올림)

## 4. 손익 집계

| 엔티티 | 설명 | 고유 키 |
|---|---|---|
| `EmployeeCostPolicy` | 연도·고용유형별 제경비율, 판관비율 | (연도, 유형) |
| `EmployeeMonthlyCost` | 직원 월 원가 스냅샷 (월급, 제경비, 판관비, 합계) | (직원, 월) |
| `MonthlyRevenueSummary` | 프로젝트 월 손익 (프로젝트명·주관 부서 스냅샷 포함) | (프로젝트, 월) |
| `CompanyMonthlyCostSummary` | 전사 정직원 총 원가 / 배분 / 미배분 | 월 |
| `RevenueMonthClosing` | 월 마감 여부 | 월 |

계산 규칙(`ProfitCalculationService`)

```text
직원 월 원가   = 연봉 ÷ 12 × (1 + 제경비율 + 판관비율)
프로젝트 매출  = Σ 해당 월 청구일 & 발행 완료된 매출 계획 금액
프로젝트 비용  = Σ 투입 직원 월 원가 × 투입 M/M
프로젝트 이익  = 매출 − 비용   → 주관 부서에 귀속
미배분 비용    = 정직원 총 원가 − Σ 정직원 원가 × 투입 M/M (삭제된 프로젝트 제외)
```

## 5. 계정 / 권한

| 엔티티 | 설명 |
|---|---|
| `Account` | 직원 1명당 1개. 이메일 아이디, BCrypt 비밀번호, 활성 여부, 로그인 실패 횟수(5회 이상 잠김) |
| `Permission` | 권한 코드 정의 (시드) |
| `PermissionGroup` | 권한 그룹. `SYSTEM` 그룹은 구성 변경 불가 |
| `GroupPermissionGrant` | 그룹에 부여된 (권한, 범위) |
| `AccountGroupAssignment` | 계정 ↔ 그룹 |

자세한 내용은 [권한가이드](권한가이드.md)를 참고하세요.

## 6. 부가 기능

| 엔티티 | 설명 |
|---|---|
| `Notification` | 계정별 알림 (프로젝트 투입, 계정 발급 등) |
| `ChatSession` / `ChatMessage` | AI 어시스턴트 대화 세션과 화면 표시용 전체 메시지 |
| `ChatMemoryMessage` | LLM 컨텍스트용 최근 메시지 창 (Spring AI `ChatMemoryRepository` 구현) |
| `WeeklyReport` | 주간 운영 보고서 초안 (AI 또는 템플릿 생성, 편집 가능) |
